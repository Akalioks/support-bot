# AI Support Assistant for Telegram

[Русская версия](README.ru.md) · **Live demo: [@SmartSupport2026_bot](https://t.me/SmartSupport2026_bot)**

A customer support bot for an online store. It answers 24/7 strictly from the company's own documents — price list, FAQ, delivery and return policies — and hands the chat to a live manager when it can't help. Answers are generated by **Google Gemini**.

The demo is built for a fictional home goods store, **Nordic Home**. The knowledge base lives in `knowledge/nordic_home.md`.

## Features

**Customer**
- Asks in their own words in English, Russian or Estonian and gets an answer in 1–4 seconds.
- The bot answers only from the knowledge base. If the answer isn't there, it says so and offers a manager instead of making things up.
- Remembers the recent conversation; `/reset` clears that memory.
- When the customer asks for a person, complains, or asks about a specific order, the bot offers a **"Connect me with a manager"** button.
- **👤 Talk to a human** calls a manager at any time; `/bot` hands the chat back to the assistant.

**Manager** (IDs in `ADMIN_IDS`)
- Receives a "Request #N" with the customer's recent messages.
- Replies to the customer's message (swipe to reply) and the answer goes to that customer; photos and files work too.
- **✅ Close** ends the conversation and the assistant takes over again — it sees what the manager wrote.

**Owner** (`/admin`)
- Stats for today and the last 7 days: AI answers, users, hand-offs, tokens used, and cost if prices are set.
- Knowledge base: view, add (a .txt / .md / .pdf file or plain text in the chat) and delete documents.
- List of open requests.

**Reliability and cost control**
- **Fallback models.** Google models are sometimes overloaded (503) or retired. The bot then tries the next model from `AI_FALLBACK_MODELS` automatically — the customer doesn't notice.
- `USER_HOURLY_LIMIT`: AI answers per person per hour (default 30).
- `DAILY_AI_LIMIT`: AI answers for everyone per day (default 500) — protects the free quota and the bill.

## AI settings (`.env`)

| Variable | Default | Description |
|---|---|---|
| `AI_MODEL` | `gemini-3.5-flash` | Main model |
| `AI_FALLBACK_MODELS` | `gemini-3.5-flash-lite,gemini-3.8-flash` | Fallback models, tried in order |
| `AI_THINKING` | `minimal` | How much the model "thinks" before answering: `minimal` (fastest, ~3 s) / `low` / `medium` / `high`. `minimal` is enough for FAQs. |
| `AI_PRICE_INPUT`, `AI_PRICE_OUTPUT` | empty | Price per 1M tokens in $, only for the cost estimate in `/admin`. Leave empty on the free tier. |

Models change quickly (for example, `gemini-2.5-flash` is no longer available for new keys). If the logs show a 404, change the model in `.env`.

## Tested live

Real requests to Gemini with the Nordic Home knowledge base:
- "How much is delivery to Tartu?" (in Russian) → exact answer in Russian: €4.90, 1–2 days, parcel lockers €2.90, free from €50.
- "Kas saab osamaksetega maksta?" → answer in Estonian: yes, via Esto, from €60.
- "Where is my order #5531? I'm annoyed!" → the bot apologises and **hands off to a manager**.
- "Do you sell bicycles?" → "no, we sell home goods" and an offer to talk to a manager. Nothing invented.

## Demo mode

With `DEMO_MODE=true` anyone can open a **read-only** `/admin` panel. Stats show only the visitor's own numbers and nothing can be edited. "Talk to a human" requests go to the IDs in `ADMIN_IDS`.

## Why no vector database (RAG)

A small business knowledge base is usually a few dozen pages. It fits entirely into the model's context, so answers are more accurate than with chunk retrieval, and updates are instant — no indexing. Vector search only pays off with hundreds of megabytes of documents.

## Run locally

1. Create a **new** bot in @BotFather (each bot needs its own token).
2. On **aistudio.google.com** click **Get API key** and create a key.
3. In the project folder (PowerShell):

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
```

4. Fill in `BOT_TOKEN`, `GEMINI_API_KEY` and `ADMIN_IDS` in **`.env`** (not in `.env.example`).
5. Start the bot:

```powershell
.venv\Scripts\python -m bot
```

On first start the bot loads every `.md` and `.txt` file from `knowledge/` into the knowledge base. For a real business, replace them with its documents and delete `support.db`.

## Tests

```powershell
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
```

20 tests. They exercise the Gemini layer through a fake client (response format, safety blocks, key and network errors, fallback models) and replay every dialog through a fake Telegram: question → answer, hand-off and manager replies, closing a request, limits, demo mode and knowledge base editing. No quota or internet needed.

## Project structure

```
bot/
  __main__.py      entry point
  app.py           dispatcher setup
  config.py        settings from .env
  ai.py            Gemini requests, fallback models, response parsing
  db.py            tables: users, messages, docs, tickets, relays
  repo.py          database queries
  texts.py         fixed texts
  keyboards.py     buttons
  handlers/
    client.py      customer questions, hand-off to a manager
    admin.py       manager replies, owner panel, knowledge base
knowledge/         documents loaded on first start
tests/
```
