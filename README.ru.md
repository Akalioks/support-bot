# AI Support Assistant: ИИ-бот поддержки

Бот поддержки для интернет-магазина. Он отвечает клиентам круглосуточно, строго по документам компании: прайсу, FAQ, условиям доставки и возврата. Если вопрос ему не по силам, бот передаёт чат живому менеджеру. Ответы пишет **Google Gemini**.

Демо сделано для вымышленного магазина товаров для дома **Nordic Home**. База знаний лежит в `knowledge/nordic_home.md`.

## Что умеет

**Клиент**
- Пишет вопрос своими словами на английском, русском или эстонском, бот отвечает за 1–4 секунды.
- Бот отвечает только по базе знаний. Если ответа там нет, он честно говорит «не знаю» и предлагает менеджера, а не выдумывает.
- Бот помнит последние сообщения разговора. Команда `/reset` стирает эту память.
- Если клиент сам просит человека, жалуется или вопрос касается конкретного заказа, бот предлагает кнопку **«Connect me with a manager»**.
- Кнопка **👤 Talk to a human** вызывает менеджера в любой момент, команда `/bot` возвращает разговор к ассистенту.

**Менеджер** (ID в `ADMIN_IDS`)
- Получает заявку «Request #N» с последними сообщениями клиента.
- Отвечает через «Ответить» (свайп влево) на сообщение клиента, и ответ уходит этому клиенту. Можно отправлять фото и файлы.
- Кнопкой **✅ Close** завершает разговор, после чего клиента снова обслуживает ассистент. Ассистент видит, что написал менеджер.

**Владелец** (`/admin`)
- Статистика за сегодня и за 7 дней: ответы ИИ, люди, передачи менеджеру, потраченные токены. Если задать цены, панель показывает и стоимость.
- База знаний: просмотр, добавление (файл .txt/.md/.pdf или просто текст в чат), удаление.
- Список открытых заявок.

**Надёжность и расходы**
- **Запасные модели.** Модели Google иногда перегружены (ошибка 503) или снимаются с поддержки. Тогда бот сам пробует следующую модель из `AI_FALLBACK_MODELS`, и клиент ничего не замечает.
- `USER_HOURLY_LIMIT`: сколько ответов ИИ получает один человек в час (по умолчанию 30).
- `DAILY_AI_LIMIT`: сколько ответов бот даёт всем вместе за день (по умолчанию 500). Это защищает от исчерпания бесплатной квоты и от счёта.

## Настройки ИИ (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `AI_MODEL` | `gemini-3.5-flash` | Основная модель |
| `AI_FALLBACK_MODELS` | `gemini-3.5-flash-lite,gemini-3.8-flash` | Запасные модели, используются по очереди |
| `AI_THINKING` | `minimal` | Сколько модель «думает» перед ответом: `minimal` (быстрее всего, около 3 с) / `low` / `medium` / `high`. Для FAQ хватает `minimal`. |
| `AI_PRICE_INPUT`, `AI_PRICE_OUTPUT` | пусто | Цена за 1M токенов в $, только для оценки стоимости в `/admin`. На бесплатном тарифе оставьте пустыми. |

Модели меняются быстро. Например, `gemini-2.5-flash` уже недоступна для новых ключей. Если в логах появится ошибка 404, замените модель в `.env`.

## Проверено вживую (24.11.2026)

Реальные запросы к Gemini с базой знаний Nordic Home:
- «Сколько стоит доставка в Тарту?» → точный ответ на русском: €4,90, 1–2 дня, почтоматы €2,90, бесплатно от €50.
- «Kas saab osamaksetega maksta?» → ответ на эстонском: да, через Esto, от €60.
- «Where is my order #5531? I'm annoyed!» → бот извиняется и **передаёт менеджеру** (needs_human).
- «Do you sell bicycles?» → «нет, мы продаём товары для дома» и предложение менеджера. Ничего не выдумано.

## Демо-режим

`DEMO_MODE=true`: любой может открыть `/admin` и посмотреть панель **только для чтения**. В статистике он видит только свои цифры, редактировать ничего не может. Заявки «позвать человека» приходят **вам**, на ID из `ADMIN_IDS`.

## Почему без векторной базы (RAG)

У малого бизнеса база знаний обычно занимает десятки страниц. Она целиком помещается в запрос к модели, поэтому ответы точнее, чем при поиске кусков текста. Обновление тоже проще: документ сразу работает, ничего не надо индексировать. Векторный поиск нужен, только если документов сотни мегабайт.

Клиенту это можно объяснять так: *«No vector database to maintain — the assistant reads your whole knowledge base on every question, so it never misses the relevant part.»*

## Запуск

1. Создайте **нового** бота в @BotFather. BookMe не используйте: у каждого бота свой токен.
2. На **aistudio.google.com** нажмите **Get API key** и создайте ключ.
3. Выполните в папке проекта (PowerShell):

```powershell
python -m venv .venv
```
```powershell
.venv\Scripts\pip install -r requirements.txt
```
```powershell
copy .env.example .env
```

4. В **`.env`** (а не в `.env.example`) заполните `BOT_TOKEN`, `GEMINI_API_KEY` и `ADMIN_IDS`.
5. Запустите бота:

```powershell
.venv\Scripts\python -m bot
```

При первом запуске бот загрузит в базу знаний все `.md` и `.txt` файлы из папки `knowledge/`. Под реального клиента замените их его документами и удалите `support.db`.

> Ключ Gemini никому не показывайте и не загружайте на GitHub. Файл `.env` уже указан в `.gitignore`, а `.env.example` должен оставаться пустым шаблоном.

## Тесты

```powershell
.venv\Scripts\pip install -r requirements-dev.txt
```
```powershell
.venv\Scripts\python -m pytest
```

20 тестов. Они проверяют запрос к Gemini через поддельный клиент: формат ответа, блокировки безопасности, ошибки ключа и сети, переход на запасную модель. Также они проигрывают все диалоги через поддельный Telegram: вопрос → ответ, передачу менеджеру и его ответ, закрытие заявки, лимиты, демо-режим и редактирование базы знаний. Тесты не тратят квоту и не требуют интернета.

## Структура

```
bot/
  __main__.py      запуск
  app.py           сборка диспетчера
  config.py        настройки из .env
  ai.py            запрос к Gemini, запасные модели, разбор ответа
  db.py            таблицы: users, messages, docs, tickets, relays
  repo.py          запросы к базе
  texts.py         фиксированные тексты
  keyboards.py     кнопки
  handlers/
    client.py      вопросы клиентов, передача менеджеру
    admin.py       ответы менеджера, панель, база знаний
knowledge/         документы, которые загружаются при первом запуске
tests/
```
